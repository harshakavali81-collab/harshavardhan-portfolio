02 / The problem

The real challenge behind the screen.

Raw orders include duplicates, invalid lines, multiple status types and category/customer dimensions. Treating cancelled or returned lines as completed revenue creates misleading KPIs; summing distinct customer counts across filters can also inflate totals.

Project workflow — authored summary
Synthetic orders→Validate & quarantine→SQL / Pandas→RFM & cohort KPIs→Dashboards & report
Simplified explanation; refer to repository architecture files for exact components.
03 / Process & actions

How the system came together.

01

Generate and validate data

Use a fixed random seed, inspect 72,388 source lines, remove 100 duplicate identifiers and quarantine 60 invalid lines.

02

Model recognized revenue

Apply transaction-time price and discount logic; recognize revenue and cost only for completed order lines, not returns/cancellations.

03

Reconcile the pipeline

Run SQL analytical queries and pandas transformations against the same cleaned data; cross-check revenue, profit and order totals.

04

Analyze customers and trends

Build 14 SQL analytical queries plus RFM segments, retention cohorts, monthly charts and KPIs.

05

Deliver and verify

Provide offline interactive HTML, Streamlit, Excel/report outputs and four automated business tests; document missing native Power BI validation.

06 / Key takeaways

What mattered, and what comes next.

  • Reliable KPI definitions and accounting status rules matter as much as attractive charts.
  • Reconciling independent SQL and Python computations creates a useful trust check.
  • Future improvements: independently verify native Power BI refresh, test real licensed data and assess how segmentation holds up beyond synthetic assumptions.
