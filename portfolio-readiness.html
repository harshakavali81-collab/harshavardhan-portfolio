DETAILED TECHNICAL STANDARD · REFERENCE, NOT CERTIFICATION

36 technical checks for portfolio projects.

These are criteria to examine in the actual repositories. The list does not mean that all 31 repositories have passed every test, or that authentication, Docker or cloud services are mandatory for simple notebooks.

1. Programming fundamentals — six checks
  1. A programming language used competently
  2. Functions, classes, modules and data structures where relevant
  3. Readable code with sensible naming
  4. Git and version control
  5. Basic algorithms and time complexity for software roles
  6. Input validation and error handling
2. Application engineering — six checks
  1. A working frontend, backend or analytical workflow appropriate to the role
  2. API and HTTP fundamentals for web applications
  3. Database design and SQL query skills
  4. Separate configuration from application code
  5. Dependency and environment management
  6. Clear component and architecture boundaries
3. Quality and reliability — six checks
  1. Automated tests for important behavior
  2. Manual walkthroughs of critical user flows
  3. Expected handling for invalid inputs and failures
  4. Reproducible setup documentation
  5. No dead navigation or controls
  6. Documented current limitations
4. Deployment and operations — six checks
  1. Local installation instructions
  2. Live deployment or honest alternative demo evidence
  3. Environment variables for deployment-specific configuration
  4. Clear service start commands
  5. Relevant logs and monitoring notes
  6. CI automated checks where appropriate
5. Security and privacy — six checks
  1. No committed keys, credentials or private tokens
  2. Sanitized environment-variable example files
  3. Safe handling of uploads and user input
  4. Authentication and authorization where needed
  5. Minimal data collection and privacy-conscious logging
  6. Reviewed dependencies and basic security precautions
6. Professional presentation — six checks
  1. Accurate README and project summary
  2. Real screenshots, demos and results
  3. Working resume and repository links
  4. Consistent LinkedIn, GitHub, resume and portfolio wording
  5. Accessible, mobile-responsive layout
  6. No fabricated metrics, testimonials or employment claims
