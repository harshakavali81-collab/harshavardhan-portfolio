01 / 19 Project title

Multilingual Indian Language Knowledge Base Platform

02 / 19 Business problem

Many document repositories are difficult to search when users ask questions across different Indian languages.

03 / 19 Objective

Accept documents and answer user questions with retrieved supporting context, while reporting when fallback logic is used.

04 / 19 Target users

Students, researchers and knowledge-base users exploring multilingual documents.

05 / 19 My contribution

Repo-backed application and technical documentation. The exact individual contribution beyond the published repository has not been independently established.

06 / 19 Technology stack

React/Vite · Python FastAPI · SQLite for local use · PostgreSQL with Docker · optional LaBSE / Sentence Transformers · optional Groq.

07 / 19 Features

Text and text-PDF ingestion, language identification, source references, chat history, statistics, exports and optional API integration.

08 / 19 Architecture

React UI → FastAPI routes → document parser and persistence → language identification → retrieval backend → grounded or extractive answer.

09 / 19 Workflow

Upload content → store/index → ask question → detect language → retrieve candidates → respond with source references and fallback notice.

10 / 19 Data

User-supplied documents stored locally; the repository warns that scanned images/PDFs are not OCR-ready by default.

11 / 19 Screenshots

See repository documentation, diagrams and UI files; no independent screenshot capture is represented as a live application.

12 / 19 Live demonstration

README documents local React and FastAPI execution. A public production URL has not been confirmed.

13 / 19 Source code

Public multilingual GitHub repository with documented application source.

14 / 19 Testing

Backend pytest suite and frontend build/lint instructions are described in README; current CI run outcome was not rechecked here.

15 / 19 Performance

No independently verified recall, latency, accuracy or live-traffic performance metric is claimed.

16 / 19 Security

Environment settings separate API credentials; the README describes optional shared-key demonstration access and production deployment guidance, not a security audit.

17 / 19 Limitations

Optional model download and API keys; deterministic hashing fallback differs from multilingual-transformer retrieval; OCR is not included for scans.

18 / 19 Future scope

Create an annotated multilingual evaluation set, report grounded-answer accuracy, and verify end-to-end hosted access.

19 / 19 Reproducibility

README provides Python environment, pip install, uvicorn, npm/Vite and pytest commands, plus Docker Compose instructions.

03 / FORECASTING + INVENTORY

DemandPilot AI — Forecasting & Inventory

Machine Learning · FastAPI · Streamlit · Simulated retail portfolio project

Source repository ↗Companion case study ↗
1. Synthetic sales2. Chronological model3. Inventory optimizer4. FastAPI + dashboard

01 / 19 Project title

DemandPilot AI — Demand Forecasting and Inventory Optimization

02 / 19 Business problem

Stock planning requires forecasts with time-safe validation and meaningful reorder assumptions.

03 / 19 Objective

Demonstrate synthetic SKU/store demand forecasts, model comparisons, reorder quantities and a reproducible dashboard.

04 / 19 Target users

Retail inventory analysts and junior data/ML engineers studying forecasting decisions.

05 / 19 My contribution

The public repo documents data validation, time-lagged features, model training, FastAPI and Streamlit integrations; it is a portfolio demo, not professional client work.

06 / 19 Technology stack

Python, Pandas, LightGBM, scikit-learn, FastAPI, SQLite, Streamlit, Plotly and optional Docker Compose.

07 / 19 Features

Synthetic store/SKU generation, baseline comparison, 7–90-day scenario forecasts, inventory what-if controls, CSV export and model evaluation.

08 / 19 Architecture

Simulated sales → validation → lag features → baseline/LightGBM → chronological evaluation → recursive prediction → inventory optimizer → API/Streamlit.

09 / 19 Workflow

Bootstrap synthetic data → calculate lagged features → pick model on validation WAPE → compute out-of-time test → forecast → recommend reorder quantities.

10 / 19 Data

README describes seeded 420-day synthetic sales histories for 8 products in 2 stores, with simulated stock balances; no licensed retailer dataset is used.

11 / 19 Screenshots

Source README includes an SVG model comparison and architectural diagrams; they reflect educational simulations.

12 / 19 Live demonstration

README explains local Python/FastAPI/Streamlit and Docker execution; no verified public deployment is claimed.

13 / 19 Source code

Public DemandPilot repository has a model-card, data dictionary, docs, dashboard and test directory.

14 / 19 Testing

README documents pytest and CI on supported Python versions. Exact latest GitHub Actions run was not independently checked.

15 / 19 Performance

README reports one-step holdout WAPE for LightGBM and seasonal naive on simulated data. These metrics do not validate commercial forecasts or multi-horizon production behavior.

16 / 19 Security

API schemas validate submitted values; environment configuration is documented. Production authentication and independent security evaluation are not established.

17 / 19 Limitations

Reorder risks and stockout probabilities are approximate heuristics. No authorized real sales, actual supplier leads, production monitoring or validated intervals.

18 / 19 Future scope

Add licensed real sales data, demand-censoring treatment, multi-horizon backtesting, calibrated prediction intervals and hosted monitoring.

19 / 19 Reproducibility

Repository documents pip install -e, scripts/bootstrap.py, pytest, uvicorn demandpilot.api.main:app, streamlit run dashboard/app.py and Docker Compose.

Technical and ethical evidence standard

The portfolio does not claim public deployment, commercial customers, unmeasured model accuracy, production forecasting accuracy, or a native Power BI Desktop check without independent evidence. Repo README material was reviewed; status can change and external credentials are separate from source publication. Review commits, tests, datasets and license before reuse.
