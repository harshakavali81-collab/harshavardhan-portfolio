01 / SQL · PYTHON · ANALYTICS

E-Commerce Sales & Customer Analytics

Problem + action

Raw synthetic order records included duplicates, invalid lines and non-completed transactions. The project cleans records, implements revenue-status rules, produces SQL/Python KPIs and segments customers with RFM/cohort analysis.

Evidence + limitation

Repository reports 31,581 completed valid-line orders and SQL/Python revenue reconciliation to ₹0.01. These are synthetic dataset results—not revenue generated for a business.

Practice question: How did you prevent inflated revenue reporting?

Study the project’s completed-order recognition rules and filtering of returns/cancellations. Explain how you reconciled the same KPI in SQL and Pandas. Be ready to show the exact code, rather than saying a business increased revenue.

02 / FORECASTING · MACHINE LEARNING

DemandPilot AI

Problem + action

Forecasting can leak future information through lag features and unreliable splits. This demo uses past-only features, chronological comparisons, LightGBM, and simulated reorder planning.

Evidence + limitation

Recorded one-step held-out WAPE: LightGBM 18.469% versus seasonal baseline 29.012%, using simulated sales. Multi-step and real-world demand accuracy remain unproven.

Practice question: Why not use a random train/test split?

Time-series data are ordered. Explain how random splitting or future-derived features would contaminate evaluation. Compare WAPE to a simple seasonal baseline and state which forecasting horizons were actually tested.

03 / FASTAPI · SQL · CLASSIFICATION

TransactionShield

Problem + action

Fraud-style data have class imbalance and risk of misleading accuracy metrics. The application demonstrates a synthetic risk-scoring API, database persistence and review UI with chronological evaluation.

Evidence + limitation

The documented held-out PR-AUC is just 0.0319 and recall 0.1429. The poor result is a useful lesson in honest evaluation, not proof of a bank-ready model.

Practice question: Why is high accuracy not enough for fraud detection?

With few positives, predicting everything as legitimate may appear accurate. Discuss precision, recall, PR-AUC, review workload and false positives. Acknowledge the weak documented model performance before recommending any production use.

04 / DOCUMENT Q&A · RETRIEVAL

EvidenceDesk

Problem + action

Document answers need traceable excerpts and a way to handle questions unsupported by the source. The app extracts text, chunks documents and retrieves cited evidence with a tested TF-IDF baseline.

Evidence + limitation

Recorded 16 passing tests, 23/25 answerable evidence hits and 3/5 correct abstentions on authored questions. These are not general LLM answer-accuracy claims.

Practice question: How does RAG differ from a trained classification model?

Explain retrieval, evidence chunking and grounding. Distinguish the tested lexical mode from optional semantic embeddings and optional answer-generation services. Be ready to demonstrate source citations and failed cases.

05 / POWER BI · DATA STORYTELLING

Zomato Insights Dashboard

Problem + action

Restaurant attributes are difficult to explore row by row. The dashboard organizes cuisine, location, rating and delivery fields into Power BI KPI cards and filterable visuals.

Evidence + limitation

The source project reports 9,551 restaurants, 250 cuisines and 15 countries. Those are dataset characteristics, not current Zomato totals or measurable business growth.

Practice question: What value did slicers and DAX measures add?

Discuss how viewers can filter geography, cuisine and rating attributes to understand different segments. Show the actual DAX or report artifacts available, and avoid claiming a live refresh if it was not verified.
